# 崩文预防技法

## 核心原则

崩文不是突然发生的，而是五种征兆长期累积的结果。预防崩文的根本方法不是"出了问题再救"，而是**在悬念链条还在运转时就提前交替铺垫**，让读者的注意力永远有"下一个期待"可承接，避免出现"上一个悬念揭完、下一个悬念还没开始"的真空期。

**核心心法**：
- 一个悬念正在高潮时，下一个悬念必须已经开始铺垫
- 读者注意力永远不要"无钩可挂"
- 数据指标是客观判断标准，主观感觉会骗人

---

## 操作步骤/公式

### 一、崩文五大征兆识别表

| 征兆 | 表现症状 | 数据信号 | 危险等级 |
|------|---------|---------|---------|
| **节奏失控** | 连续3章以上无钩子/无爽点；单章字数忽长忽短 | 章节完读率断崖下跌 | 🔴 高危 |
| **逻辑断裂** | 设定前后矛盾；人物能力忽强忽弱；时间线对不上 | 评论区出现"作者忘了"类评论 | 🔴 高危 |
| **人物变形** | 主角行为不符合人设；配角沦为工具人；OOC无铺垫 | 读者评论"这不像XX会做的事" | 🟡 中危 |
| **读者疲劳** | 单章信息过载；连续高潮无缓冲；情绪持续高压 | 追读率连续3章下降 | 🟡 中危 |
| **作者倦怠** | 写作像挤牙膏；每段都要硬凑；剧情推进失去方向感 | 作者自己不想写下一章 | 🔴 高危 |

### 二、悬念提前交替铺垫法（核心技法）

**操作公式**：
```
在悬念1的故事中 → 穿插悬念2的人和事
                → 同时让悬念3的人物露个面
写到悬念2时     → 继续穿插悬念3的部分故事
                → 给悬念4的露面做铺垫
```

**钩子数量底线**：每个悬念的钩子至少保持在 **1.75 个以上**（即任意时刻读者手中都有至少2个未解之谜在追踪）。

**错误时机**：不要等悬念1快结束时才铺垫悬念2——那时读者注意力还集中在悬念1上，来不及转移。

### 三、换地图正确姿势

**三要素铁律**：换地图必须同时携带"新冲突+新角色+新力量"，缺一不可。

| 要素 | 作用 | 缺失后果 |
|------|------|---------|
| 新冲突 | 立即给主角制造新压力 | 地图换了但剧情停滞 |
| 新角色 | 建立新的人物关系网 | 主角孤悬，无人互动 |
| 新力量 | 提供新的成长/对抗空间 | 战力体系僵化 |

**描写禁忌**：
- ❌ 不要过度描写主角路上的心理历程
- ❌ 不要大段铺垫目的地的环境描写
- ✅ 主角去拿东西，就写拿东西本身
- ✅ 你写的是主角完成了多少事，而不是走过了多少地方

**保底策略**：如果暂时掌握不好换地图技巧，最简单粗暴的办法是**尽量不换地图**。

### 四、差评预警与应对

**核心原则**：别让读者替你写大纲。

**真实案例**：有位作者把第一本书所有被骂的毒点全改掉了，结果第二本扑得非常惨——因为读者想要什么就立马给，反而失去了期待感。

| 差评类型 | 处理方式 | 判断依据 |
|---------|---------|---------|
| 常识性错误 | ✅ 可以改 | 设定硬伤、逻辑漏洞 |
| 剧情向建议 | ⚠️ 慎重 | 读者脑补的方向未必是你想写的 |
| 追读稳但评论骂 | ❌ 不用改 | 边骂边看=粘性高 |

**最客观的判断标准**：追更数据有没有掉？
- 追读稳 → 不改
- 追读掉 → 优先排查是哪一章开始掉的，针对性修复

## 模板/示例

### 悬念交替铺垫示例

```
【第10章·悬念1进行中】
主角正在破解娘娘庙封印（悬念1高潮）
→ 庙中发现一块刻着陌生名字的残碑（悬念2种子）
→ 残碑上的名字，第5章那个神秘老人提过一句（呼应）

【第15章·悬念2展开】
主角调查残碑来历（悬念2展开）
→ 调查过程中遇到一个新角色，他说"你来得太晚了"（悬念3种子）
→ 同时暗示主角身上的护身符有异常（悬念3铺垫）

【第20章·悬念2揭开的同章】
残碑真相揭晓（悬念2闭合）
→ 同一章结尾，新角色失踪，留下一封血书（悬念3引爆）
```

### 崩文急救流程

```
Step 1：定位崩点
  - 查看追读数据，找到哪一章开始掉
  - 重读该章及前两章

Step 2：判断征兆类型
  - 节奏失控？→ 加钩子，砍废话
  - 逻辑断裂？→ 用"补丁章"修补设定
  - 人物变形？→ 加一段符合人设的关键行动
  - 读者疲劳？→ 插入一个缓冲章+小爽点
  - 作者倦怠？→ 回退三步法找新动力

Step 3：修复但不过度修改
  - 只改影响追读的部分
  - 不改读者边骂边看的部分
```

## 自检清单

- [ ] 当前章节是否至少有 1.75 个未解悬念在运转？
- [ ] 是否存在连续2章以上无钩子的情况？
- [ ] 换地图时是否同时携带了"新冲突+新角色+新力量"三要素？
- [ ] 是否避免了"路上心理历程+目的地环境描写"的冗余？
- [ ] 收到差评时，是否先查追读数据再决定是否修改？
- [ ] 是否有意识地不让读者"想要什么就立马给"？
- [ ] 自己写作时是否出现"挤牙膏"感超过3章？（作者倦怠预警）
- [ ] 主角的行为是否符合人设？是否需要补铺垫？

## 适用边界

**适用场景**：
- 百万字长篇连载的全周期崩文预防
- 连载中后期（10万字以后）的节奏维护
- 换卷/换地图/换副本的过渡期
- 数据出现下滑信号时的诊断

**不适用场景**：
- 黄金三章阶段（此阶段重点在"建立"而非"维护"）
- 短篇/中篇作品（结构简单，不易崩文）
- 已完结作品的回顾性修改

**重要边界**：
- 本卡技法针对"预防"，不是"救火"——救火请配合 KC-SKILL-004 节奏控制公式
- 悬念交替铺垫不等于"为钩而钩"——必须有逻辑关联，不能强行堆砌
- 换地图策略不适用于"单元副本"结构——副本是独立闭环，不需要换地图
