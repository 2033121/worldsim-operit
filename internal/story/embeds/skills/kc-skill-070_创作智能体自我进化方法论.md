# KC-SKILL-070 · 创作智能体自我进化方法论

> **一句话定位：** 让AI辅助创作系统"只犯一次错"的底层方法论——构建「创作→校验→反馈→学习→优化」的闭环自我进化系统，使错误不再重复、反馈自动吸收、能力持续迭代。

---

## 一、自我进化的本质：闭环正反馈系统

### 1.1 核心认知

传统AI辅助创作：每次创作都是"从零开始"，同样的错误反复出现。

自我进化系统：构建完整的正反馈闭环，不需要人工干预，自动完成「创作-校验-反馈-学习-优化」全流程，使系统越用越精准。

### 1.2 闭环工作流架构

```
┌─────────────────────────────────────────────────┐
│                                                   │
│  A[创作任务触发]                                  │
│   ↓                                               │
│  B[加载历史记忆库] ←─────────────────────┐       │
│   ↓                                      │       │
│  C[基于规则+记忆进行创作]                 │       │
│   ↓                                      │       │
│  D[自动触发自我校验]                      │       │
│   ↓                                      │       │
│  E{校验是否通过?}                        │       │
│   ├─是→ F[输出最终内容] → H[接收用户反馈]│       │
│   └─否→ G[自动修正错误] → 回到C          │       │
│                                          ↓       │
│  I[自动解析反馈,提取错误/优化点] ────────┘       │
│   ↓                                               │
│  J[更新记忆库,记录错误+修正方案] ───────→ B      │
│                                                   │
└─────────────────────────────────────────────────┘
```

### 1.3 三大核心能力

| 能力 | 内涵 | 价值 |
|:-----|:-----|:-----|
| **记忆优先** | 所有创作先加载历史记忆库，之前的错误绝不犯第二次 | 避免重复踩坑 |
| **自我校验** | 创作完成后自动执行校验清单，检查所有问题 | 质量内嵌而非外挂 |
| **反馈吸收** | 用户反馈自动解析为结构化错误信息，永久存入记忆库 | 越用越精准 |

## 二、自然触发机制：无人工干预的自动运行

> 所有校验、学习、修正动作都是自然触发的，不需要手动输入指令。

### 2.1 创作前触发

| 触发动作 | 执行内容 |
|:---------|:---------|
| 自动加载记忆 | 接收创作任务后，第一时间加载历史记忆库，把所有犯过的错误、修正方案、优化规则注入上下文 |
| 自动规则匹配 | 根据创作类型自动匹配对应规则（如中式克苏鲁的避坑指南、规则怪谈的元素要求） |

### 2.2 创作中触发

| 触发动作 | 执行内容 |
|:---------|:---------|
| 实时错误拦截 | 每完成一个段落，自动检查是否命中历史错误库（内容重复、元素堆砌、错误设定） |
| 实时逻辑校验 | 自动检查当前内容有无逻辑漏洞（规则矛盾、污染表达错误、设定不一致） |

### 2.3 创作后触发

| 触发动作 | 执行内容 |
|:---------|:---------|
| 全内容自检 | 创作完成后，自动执行完整的自我校验清单 |
| 自动修正 | 发现问题后，自动根据记忆库的修正方案修正 |
| 反馈自动吸收 | 用户给出反馈后，自动解析、提取错误和修正方案，存入记忆库 |

## 三、错误记忆库：让错误只犯一次

### 3.1 记忆库核心原则

> **只犯一次原则**：所有的错误只允许犯一次，第二次绝对不能再犯。记忆库是永久的，只要存入的错误和修正方案，永远有效。

### 3.2 错误存储结构

每一条错误记忆按以下结构存储，方便检索和调用：

```json
{
  "错误ID": "唯一标识",
  "错误类型": "格式错误/逻辑错误/创作规则错误/文化符号错误",
  "错误场景": "中式克苏鲁创作/规则怪谈创作/...",
  "错误描述": "具体的错误内容",
  "触发条件": "什么情况下会出现这个错误",
  "修正方案": "具体的修正方法",
  "出现次数": 1,
  "最后更新时间": "时间戳"
}
```

### 3.3 错误四大分类

| 错误类型 | 典型问题 | 修正方向 |
|:---------|:---------|:---------|
| **格式错误** | 内容重复输出、Markdown格式错乱、图片链接失效 | 输出前全文查重、格式校验 |
| **创作规则错误** | 把克苏鲁当世界观、元素堆砌、照搬西式设定、破坏恐怖氛围 | 严格遵循题材创作规则 |
| **逻辑错误** | 规则没分层、污染表达不符语境、核心写得太清楚 | 补充分层规则、留白处理 |
| **文化符号错误** | 正面符号用错、民俗元素误用、不符合中式精神 | 锚定文化基底、符号校验 |

### 3.4 记忆库进化规则

| 触发条件 | 自动动作 |
|:---------|:---------|
| 同一错误出现≥2次 | 升级系统提示词优先级 |
| 错误频率下降50% | 降级监控等级 |
| 新错误类型出现 | 自动生成规避策略并入库 |

## 四、反馈吸收逻辑：自动学习的核心

### 4.1 反馈处理五步法

```
第一步：解析反馈
  ↓ 把自然语言反馈转化为结构化错误信息
  ↓ （如"上次的文档内容重复了" → 错误类型:格式错误, 描述:段落重复, 修正:输出前查重）
  ↓
第二步：更新记忆库
  ↓ 把错误信息存入记忆库，永久保存
  ↓
第三步：规则更新
  ↓ 把修正方案加入到自我校验清单
  ↓
第四步：生效
  ↓ 下次任何创作任务，自动加载这个记忆，自动避免这个错误
  ↓
第五步：验证
  ↓ 持续监控该错误是否再次出现，确认修正有效
```

### 4.2 反馈吸收的关键原则

- **不需要用户确认**：自动处理，自动更新
- **永久生效**：只要存入，永远有效
- **结构化存储**：自然语言转化为可检索的结构化数据
- **闭环验证**：修正后持续监控，确保有效

## 五、自我校验清单：创作完成后的自动检查

### 5.1 基础格式校验

- [ ] 全文有无重复段落、重复内容
- [ ] Markdown格式有无错误（标题、列表、链接）
- [ ] 图片链接是否有效
- [ ] 排版是否清晰

### 5.2 创作规则校验

- [ ] 有无违反题材核心规则（如把克苏鲁当世界观、元素堆砌）
- [ ] 有无照搬不适合的设定（如西式SAN值用于中式恐怖）
- [ ] 有无破坏题材氛围（如恐怖文让主角轻易叫救援）
- [ ] 有无保留题材核心精神（如中式的进取精神）

### 5.3 专项规则校验（按题材适配）

| 题材 | 专项校验项 |
|:-----|:-----------|
| 规则怪谈 | 规则是否分层、是否有矛盾、核心是否留白、代价是否可视化 |
| 中式克苏鲁 | 污染表达是否中式、有无绝对绝望、文化基底是否锚定 |
| 玄幻修仙 | 战力体系是否一致、境界规则是否统一、人设是否OOC |
| 都市现实 | 现实逻辑是否闭环、人设行为是否符合身份、剧情是否悬浮 |

### 5.4 历史错误校验

- [ ] 有无命中历史记忆库中的错误
- [ ] 有无按照之前的修正方案执行
- [ ] 新出现的错误是否已存入记忆库

## 六、多作品自适应规则

### 6.1 作品自动识别

| 识别优先级 | 识别方式 |
|:-----------|:---------|
| 最高 | 当前对话中明确提到的作品名、主角名、核心世界观关键词、专属设定术语 |
| 次高 | 最近3轮对话中高频出现的作品相关信息 |
| 默认 | 最近正在更新/修改的作品 |
| 新建 | 识别到未建档的作品信息，自动触发新作品建档流程 |

### 6.2 多作品隔离原则

- 每本作品的档案完全独立，设定、人设、规则、红线物理隔离
- **绝对禁止跨作品串设定、串人设**
- 同一作品的规则迭代，自动同步更新到该作品总档案
- 后续所有创作必须遵循最新版规则

## 七、系统部署核心要素

### 7.1 七大核心模块

| 模块 | 功能 | 更新频率 |
|:-----|:-----|:---------|
| 项目DNA | 类型、核心主题、目标受众、字数计划 | 项目初始化，极少变更 |
| 世界系统 | 核心世界规则、世界索引 | 随世界成长添加新规则 |
| 角色档案 | 角色索引、关系网络 | 添加新角色或关系重大变化时 |
| 情节与结构 | 故事结构、大纲索引 | 整体稳定，章节细分可调整 |
| 文风指南 | 基调、语言、对话风格、节奏规则 | 纠正AI写作风格时随时调整 |
| 注意事项与软约束 | 叙事禁忌、用户约束 | 从反馈中学习 |
| 实时写作状态 | 当前状态、角色快照、待处理线索 | 每次写作会话后自动更新 |

### 7.2 自动更新触发器

| 触发事件 | 自动更新内容 |
|:---------|:---------|
| 完成一章 | 实时写作状态（最近情节流、角色快照） |
| 完成任务 | 项目路线图（待办列表、里程碑日志） |
| 添加新角色 | 角色档案（角色索引） |
| 建立新规则 | 世界系统（核心世界规则） |
| 请求修订 | 注意事项与软约束（学习偏好并添加约束） |

## 九、使用建议

### 9.1 系统初始化

1. **建立初始记忆库**：预设该创作领域的常见错误和修正方案
2. **配置创作规则**：明确题材核心规则、文化基底、禁忌内容
3. **设置校验清单**：按基础格式+创作规则+专项规则+历史错误四层配置

### 9.2 日常使用

- **每次创作前**：确认记忆库已加载，规则已匹配
- **创作过程中**：关注实时错误拦截提示
- **创作完成后**：查看自我校验报告，确认无问题后输出
- **收到反馈后**：确认反馈已自动解析并存入记忆库

### 9.3 持续优化

- **每周复盘**：查看本周新增的错误记忆，确认修正方案有效
- **每月进化**：评估错误频率趋势，调整监控等级
- **每卷结束**：全量校验记忆库，清理过时规则，升级核心规则

## 十、避坑指南

| 常见误区 | 后果 | 规避方法 |
|:---------|:-----|:---------|
| 记忆库不结构化 | 检索效率低，无法自动调用 | 用统一JSON结构存储，支持快速检索 |
| 校验清单太庞大 | 每次校验耗时过长，影响创作效率 | 按优先级分层，核心规则必查，细节规则抽样查 |
| 反馈不自动解析 | 依赖人工维护，无法持续进化 | 建立自然语言→结构化数据的自动解析机制 |
| 跨作品记忆串档 | A书规则污染B书创作 | 多作品档案物理隔离，加载前先做作品识别 |
| 只记录错误不记录成功经验 | 错误越来越少但好经验不积累 | 正向模式也存入记忆库，标注为"成功模式" |
