# 修改润色SOP

## 一、核心原则：好文章是改出来的

> 初稿是把字写在纸上，修改是把字刻进心里。

**核心认知：**
```
作品质量 = 初稿底子 × 修改次数 × 修改深度
```

**三大底层原则：**

### 原则1：修改不是"改对"，是"改好"
- "改对"是纠错——改错别字、改逻辑漏洞，这是底线
- "改好"是提质——让节奏更爽、情感更戳、人物更活，这是上限
- 初稿追求"写完"，修改追求"写好"，目标完全不同

### 原则2：从大到小改，先改结构再改字句
- 顺序错了等于白改——如果整段要删，字句改得再漂亮也没用
- 宏观决定下限，微观决定上限
- 七轮修改法严格遵循：结构 → 人设 → 节奏 → 情感 → 语言 → 逻辑 → 校对

### 原则3：每轮只关注一个层面
- 一轮改多个维度 = 哪个都改不深
- 专注才能发现问题——看结构的时候就别看错别字
- 每轮有明确的检查清单和修改动作，完成即进入下一轮

---

## 二、七轮修改法（从宏观到微观）

### 第一轮：结构审查——大纲层面，有没有跑偏、有没有崩

**核心目标：** 确保故事骨架是对的，大方向没歪。

**检查内容：**
- [ ] **主线清晰度**：读者能不能用一句话说清楚这本书讲了什么？
- [ ] **节奏合理性**：有没有头重脚轻？有没有某一卷特别水？
- [ ] **伏笔回收**：埋的坑都填了吗？有没有挖了忘了的？
- [ ] **人物弧光**：主角从开头到结尾，有没有成长/改变？
- [ ] **结构完整性**：起承转合齐全吗？开头吸引人吗？结尾收得住吗？

**调用知识卡：**
- **KC-SKILL-012 五级漏斗大纲**：用大纲倒推结构问题
- **KC-SKILL-019 伏笔系统**：核对伏笔清单，确保全部回收
- **KC-SKILL-010 结局设计矩阵**：检查结局是否合理、是否有力

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 主线跑偏 | 删大段无关剧情，把主线拉回来 | 🔴 最高 |
| 节奏失衡 | 调整章节顺序，合并/拆分卷 | 🔴 最高 |
| 伏笔没回收 | 补铺垫、收伏笔，或删除不重要的伏笔 | 🟡 中等 |
| 人物弧光缺失 | 补成长节点、加关键事件 | 🟡 中等 |
| 结尾无力 | 重写结局，或增加收尾章节 | 🔴 最高 |

**操作方法：**
1. 先写一句话梗概，看看能不能说清楚
2. 列每卷的核心事件，画一条曲线图，看起伏是否合理
3. 拿出伏笔清单，逐个核对状态（已回收/未回收/已遗忘）
4. 对比人物初始状态和最终状态，看变化是否足够

---

### 第二轮：人设审查——人物层面，OOC了没

**核心目标：** 确保人物行为符合人设，人物关系合理可信。

**检查内容：**
- [ ] **人物行为一致性**：这个人会不会说出这句话、做出这件事？
- [ ] **人物关系合理性**：他们的关系发展符合逻辑吗？
- [ ] **人物成长线**：人物的变化有铺垫吗？是渐变还是突变？
- [ ] **配角工具人化**：配角有没有自己的动机和性格？
- [ ] **对话辨识度**：遮住名字，能不能猜出是谁说的话？

**调用知识卡：**
- **KC-SKILL-001 五步塑造法**：用五维模型核对人物立体度
- **KC-SKILL-040 人物关系化学反应**：检查人物关系是否有张力

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 严重OOC | 调整动机、改行为方式，或重写该段 | 🔴 最高 |
| 对话千人一面 | 改对话风格，给每个人加口头禅/说话习惯 | 🟡 中等 |
| 人物关系突兀 | 补互动细节、加关系递进的过程 | 🟡 中等 |
| 人物扁平 | 补人物反应、加内心戏、增加反差面 | 🟡 中等 |
| 配角工具人 | 给配角加自己的小目标和小性格 | 🟢 低 |

**操作方法：**
1. 挑3-5段关键剧情，遮住名字看对话，测试辨识度
2. 找出人物最大的3个性格标签，核对关键选择是否符合
3. 拉出主要人物关系线，看每一步进展是否有铺垫
4. 随机抽查10个配角，看有没有自己的名字和特点

---

### 第三轮：节奏审查——情节层面，爽不爽、卡不卡

**核心目标：** 确保阅读体验流畅，爽点够，钩子足，不拖沓。

**检查内容：**
- [ ] **水段落检测**：有没有删掉也不影响剧情的段落？
- [ ] **爽点密度**：平均几章一个小爽点？几卷一个大爽点？
- [ ] **钩子强度**：每章结尾有没有让人想点下一章的欲望？
- [ ] **节奏快慢**：整体节奏是偏快还是偏慢？有没有该快不快、该慢不慢？
- [ ] **信息密度**：每一章有没有提供新信息？

**调用知识卡：**
- **KC-SKILL-004 节奏控制公式**：用节奏公式校准整体节奏
- **KC-SKILL-003 钩子九连环**：检查章末钩子质量
- **KC-SKILL-025 爽点类型与密度**：核对爽点类型和分布

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 严重水文 | 大段删除，毫不留情 | 🔴 最高 |
| 爽点不足 | 加爽点、提前爽点、放大爽点 | 🔴 最高 |
| 钩子太弱 | 重写章末，补悬念、留疑问 | 🟡 中等 |
| 节奏太慢 | 删铺垫、提速、合并过渡章 | 🟡 中等 |
| 节奏太快 | 加细节、补反应、拉长高潮 | 🟢 低 |

**操作方法：**
1. 速读模式：快速翻一遍，哪些地方想跳过？那些就是水段落
2. 标记法：用不同颜色标记爽点、钩子、过渡，看密度是否合理
3. 章末测试：随机抽10章结尾，看自己想不想看下一章
4. 信息增量检查：每章看完问自己——这一章告诉我什么新东西了？

---

### 第四轮：情感审查——情绪层面，动不动人

**核心目标：** 确保情感真实可信，情绪到位，读者能代入。

**检查内容：**
- [ ] **情感真实性**：这个情绪反应合理吗？会不会太假？
- [ ] **情绪到位度**：该哭的时候有没有让人想哭？该爽的时候有没有让人爽到？
- [ ] **CP感强度**：读者会不会磕这对？会不会为他们着急？
- [ ] **情感铺垫**：情绪爆发前有没有足够的铺垫？
- [ ] **情感细节**：有没有具体的细节让情感落地？

**调用知识卡：**
- **KC-SKILL-035 情感线设计系统**：核对情感线五阶段
- **KC-SKILL-005 情绪曲线设计**：检查情绪起伏是否合理
- **KC-SKILL-007 情感描写技巧**：提升情感描写质量

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 情感突兀 | 补情感铺垫、加心理转变过程 | 🔴 最高 |
| 情绪不够 | 补情感细节、加感官描写、拉长情绪 | 🟡 中等 |
| CP感弱 | 加互动细节、补共同经历、增加反差萌 | 🟡 中等 |
| 情感空洞 | 把"我好难过"换成具体的动作和细节 | 🟡 中等 |
| 情感节奏不对 | 调整情感节点位置，配合主线节奏 | 🟢 低 |

**操作方法：**
1. 找3-5个情感高潮段落，读的时候自己有没有情绪波动？
2. 检查每个大情绪爆发前，有没有至少3个铺垫细节
3. 把所有直白的情绪形容词（"开心""难过""生气"）标出来，看看能不能换成具体描写
4. 检查CP互动：他们有多少只有彼此才懂的细节？

---

### 第五轮：语言审查——文字层面，好不好看

**核心目标：** 去除AI味，提升文字质感，让语言生动有记忆点。

**检查内容：**
- [ ] **AI味检测**：有没有典型的AI腔、模板化表达？
- [ ] **对话自然度**：对话像真人说的话吗？会不会太书面？
- [ ] **描写生动度**：有没有画面感？能不能脑补出场景？
- [ ] **金句密度**：有没有让人想摘抄的句子？
- [ ] **用词准确性**：有没有重复用词、词不达意？

**调用知识卡：**
- **KC-SKILL-041 去AI味**：系统性去除AI痕迹
- **KC-SKILL-013 对白五句式**：优化对话质量
- **KC-SKILL-030 感官五维法**：增强描写画面感
- **KC-SKILL-036 金句创作**：增加金句密度

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 严重AI味 | 替换高频词、改句式、加"不完美"表达 | 🔴 最高 |
| 对话生硬 | 口语化、加语气词、加打断和停顿 | 🟡 中等 |
| 描写空洞 | 补感官细节（视/听/嗅/味/触） | 🟡 中等 |
| 语言平淡 | 加金句、优化比喻、增加节奏感 | 🟢 低 |
| 重复用词 | 替换高频词，丰富表达方式 | 🟢 低 |

**操作方法：**
1. AI味排查：搜"微微""缓缓""轻轻""不由得""仿佛"等高频词，看是不是太多
2. 对话朗读：把对话读出来，看像不像正常人说话
3. 感官检查：随便挑一段描写，看看调动了几个感官
4. 金句标记：每卷有没有至少2-3句让人印象深刻的话

---

### 第六轮：逻辑审查——逻辑层面，通不通

**核心目标：** 消除前后矛盾、设定冲突、战力崩坏等硬伤。

**检查内容：**
- [ ] **前后一致性**：前面说A，后面是不是变成B了？
- [ ] **设定自洽性**：世界观设定有没有冲突的地方？
- [ ] **战力平衡**：战力体系崩了吗？是不是说好了很难结果很容易？
- [ ] **因果合理性**：事件的起因经过结果合理吗？有没有强行降智？
- [ ] **细节闭环**：小细节有没有前后对不上的？

**调用知识卡：**
- **KC-RULE-001 RICC规则收敛**：确保设定自洽
- **KC-SKILL-039 战力防崩三铁律**：防止战力崩坏
- **KC-RULE-002 DCRB因果补强**：强化因果逻辑

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 重大逻辑bug | 补设定、打补丁、或修改剧情 | 🔴 最高 |
| 战力崩坏 | 加限制条件、补代价、调整胜负原因 | 🔴 最高 |
| 前后矛盾 | 统一设定，修改不一致的地方 | 🟡 中等 |
| 强行降智 | 补动机、加信息差、增加合理阻碍 | 🟡 中等 |
| 小细节错误 | 直接修正 | 🟢 低 |

**操作方法：**
1. 列设定清单，逐条核对正文里有没有违反
2. 拉出关键剧情的因果链：因为A所以B所以C，看每一环是否合理
3. 战力节点标记：所有重要战斗，核对战力等级和胜负原因
4. 时间线梳理：画一条时间轴，看事件发生顺序有没有问题

---

### 第七轮：终检发布——最终检查，有没有硬伤

**核心目标：** 最后一道防线，确保没有低级错误和合规问题。

**检查内容：**
- [ ] **错别字**：有没有错字、漏字、多字？
- [ ] **标点符号**：标点使用正确吗？有没有中英文标点混用？
- [ ] **格式规范**：段落、缩进、换行是否统一？
- [ ] **敏感词**：有没有违规敏感内容？
- [ ] **政策红线**：有没有触碰政策底线的内容？

**调用知识卡：**
- **KC-RULE-004 七维质检法**：全方位质量检查
- **KC-SKILL-016 朱雀去痕**：去除AI痕迹和优化语言
- **KC-SKILL-037 商业化感知**：合规性和商业化检查

**修改动作：**
| 问题 | 修改动作 | 优先级 |
|------|---------|--------|
| 敏感内容 | 删除或替换，绝不侥幸 | 🔴 最高 |
| 政策红线 | 大段修改或删除，确保安全 | 🔴 最高 |
| 错别字 | 逐字校对修正 | 🟡 中等 |
| 标点格式 | 统一规范 | 🟢 低 |
| 排版问题 | 调整格式 | 🟢 低 |

**操作方法：**
1. 工具初检：用校对软件先过一遍
2. 人工终检：逐字读最后一遍（可以读出来，更容易发现问题）
3. 敏感词检测：用敏感词工具扫描
4. 发布前检查：标题、简介、标签有没有问题

## 三、修改优先级排序

**优先级从高到低：**
```
结构 > 人设 > 节奏 > 情感 > 语言 > 逻辑 > 校对
```

**为什么是这个顺序？**
1. **结构是地基**——地基歪了，上面装得再漂亮也没用
2. **人设是灵魂**——人物立不住，故事再精彩也没人关心
3. **节奏是体验**——节奏不对，读者根本撑不到看到你文笔好的地方
4. **情感是记忆**——情感不到位，读者看完就忘
5. **语言是质感**——语言是锦上添花，不是雪中送炭
6. **逻辑是底线**——逻辑bug会让读者出戏，但只要不严重可以接受
7. **校对是脸面**——错别字不影响内容，但影响专业形象

**时间分配参考（以深度修改为例）：**
| 轮次 | 占比 | 时间（2天计） |
|------|------|--------------|
| 结构审查 | 20% | 约4小时 |
| 人设审查 | 15% | 约3小时 |
| 节奏审查 | 20% | 约4小时 |
| 情感审查 | 15% | 约3小时 |
| 语言审查 | 15% | 约3小时 |
| 逻辑审查 | 10% | 约2小时 |
| 终检发布 | 5% | 约1小时 |

## 五、不同修改需求的简化版

### 快速修改版（约2小时）——日常更新用

**适用场景：** 日常更新、时间紧张、只求没大问题

**只做3轮：**
1. **第三轮·节奏审查**（40分钟）——删水、补钩子、加小爽点
2. **第五轮·语言审查**（60分钟）——去AI味、顺对话、调描写
3. **第七轮·终检发布**（20分钟）——错别字、敏感词、格式

**快速检查清单：**
- [ ] 这一章有没有水段落？
- [ ] 章末有没有钩子？
- [ ] 对话自然吗？
- [ ] 有没有明显的AI味？
- [ ] 有没有错别字？
- [ ] 有没有敏感词？

---

### 标准修改版（约半天）——重要章节用

**适用场景：** 上架章、高潮章、完结章、定期复盘修改

**做5轮：**
1. **第二轮·人设审查**（1小时）——确保人物不OOC
2. **第三轮·节奏审查**（1.5小时）——节奏、爽点、钩子
3. **第四轮·情感审查**（1小时）——情绪到位、CP感
4. **第五轮·语言审查**（1小时）——文字质感
5. **第七轮·终检发布**（0.5小时）——最终检查

**跳过：** 第一轮（结构）、第六轮（逻辑）——假设大方向没问题

---

### 深度修改版（1-2天）——完稿大修/重大修改

**适用场景：** 全书完稿后大修、签约前打磨、数据不好全面改版

**七轮全做：**
1. 结构审查
2. 人设审查
3. 节奏审查
4. 情感审查
5. 语言审查
6. 逻辑审查
7. 终检发布

**建议分两天进行：**
- **第一天**：前三轮（结构、人设、节奏）——改骨架
- **第二天**：后四轮（情感、语言、逻辑、终检）——填血肉

## 六、修改避坑指南

### 坑1：越改越差——改完还不如不改

**症状：** 改完再读一遍，感觉还不如原来的版本好。

**原因：**
- 修改方向错了——为了改而改，不是因为有问题才改
- 改了局部毁了整体——某段改得更精彩了，但节奏被打乱了
- 失去了初稿的灵气——初稿虽然粗糙，但有真情实感，改完变圆滑了

**解法：**
1. **修改前先备份**——每一轮修改前都存一个版本，不行就回退
2. **先诊断再开药**——先列问题清单，再针对性修改，不要瞎改
3. **改完对比读**——修改前后各读一遍，确认真的变好了再保留
4. **保留初稿的"毛边"**——不要把所有不完美都改掉，有些"毛边"是灵气

---

### 坑2：改崩了——越改问题越多

**症状：** 改了一个地方，牵一发而动全身，引出一堆新问题。

**原因：**
- 没有系统性思维——只盯着局部改，没想到会影响全局
- 改动太大——一次性改太多，失控了
- 没有验证——改完不检查，以为改对了

**解法：**
1. **小步快跑**——一次只改一个层面，改完验证没问题再进入下一轮
2. **改完马上验证**——每改一个地方，立刻读前后文，看顺不顺
3. **画改动影响图**——大改动前，先想想会影响哪些地方，提前准备
4. **实在不行就回退**——不要硬撑，回退到上一个稳定版本重来

---

### 坑3：改不完——无限修改死循环

**症状：** 改了一遍又一遍，总觉得还能更好，永远改不完。

**原因：**
- 完美主义——追求100分，但90分就够发布了
- 没有标准——不知道改到什么程度算好
- 拖延症——用"我还在改"来逃避发布

**解法：**
1. **设定修改时限**——每轮修改设时间上限，到点就停
2. **用检查清单验收**——对照清单一条条过，都过了就算完成
3. **记住：发布才是完成**——改得再好，不发布也等于零
4. **允许不完美**——80分就可以发，剩下的20分在连载中慢慢优化

---

### 坑4：只改字句不改结构——捡芝麻丢西瓜

**症状：** 改了一堆错别字、换了很多好词，但读起来还是觉得不好看。

**原因：**
- 懒——改字句容易，改结构难，下意识挑容易的做
- 看不到结构问题——不知道问题出在结构上，以为是文笔不好
- 舍不得删——自己写的东西，哪段都舍不得删

**解法：**
1. **严格按顺序来**——先改结构，结构没问题了再碰字句
2. **"kill your darlings"**——该删就删，不要心疼
3. **先删再加**——先把水分挤掉，再考虑加什么
4. 记住：**结构对了，哪怕文笔一般，也能看下去；结构错了，文笔再好也没用**

## 八、适用边界

### 适用场景
- ✅ 完稿后全书整体修改润色
- ✅ 定期回头修改已发布内容
- ✅ 上架前/签约前重点打磨
- ✅ 单章/单卷针对性修改
- ✅ 数据不好时的诊断性修改

### 不适用场景
- ❌ 初稿写作过程中（会严重拖慢速度）
- ❌ 日常快速更新（用简化版即可）
- ❌ 只有错别字等小问题（直接终检就行）
- ❌ 完全不知道问题在哪（先做诊断，再修改）

### 使用注意事项
1. **这是流程，不是教条**——根据实际情况调整顺序和重点，不要死搬硬套
2. **修改前先诊断**——先搞清楚问题在哪，再决定改哪些、改到什么程度
3. **保留备份**——每一轮修改前都备份，改崩了可以回退
4. **不要在疲惫时修改**——修改比写初稿更费脑子，状态不好时容易越改越差
5. **改完放一放再看**——刚改完容易自我感觉良好，放一天再读，问题更清楚
