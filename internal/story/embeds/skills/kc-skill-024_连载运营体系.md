# 连载运营体系

## 核心原则

1. **存稿是连载的生命线**：最少3章缓冲，老手建议10万字。没有存稿的连载如同走钢丝。
2. **数据驱动决策**：追读率、完读率、数据趋势是切书/坚持/优化的唯一客观标准，主观感觉不算数。
3. **崩文预防优先于崩文抢救**：悬念提前交替铺垫是预防崩文的核心，等到崩了再救代价极大。
4. **换地图是高风险操作**：掌握不好就尽量不换；要换就直奔目标，不写路上的心理历程和环境描写。
5. **差评不能照单全改**：读者想要什么不能立马给，追读稳但评论骂的书不用改（边骂边看）。

## 操作步骤/公式

### 步骤1：存稿策略制定

| 作者类型 | 开书前存稿 | 连载期存稿 | 推荐存稿量 |
|---------|-----------|-----------|-----------|
| **新手** | 写到2万字发书验证签约 | 签约后稳定日更4000字以上 | 5-7万字缓冲 |
| **老手** | 存10万字一次发完验证 | 日更4000-6000字（算法敏感区间） | 不低于10万字 |
| **底线** | 至少3章（约6000-9000字） | 每日产出≥每日发布 | 永远不低于3章 |

```
番茄平台章节字数特殊规则：
· 每章建议控制在 2050-2300字
· 原因：有声小说改编和平台奖励按这个字数区间计算
· 信息密度：每千字不超过 15条新设定曝光

更新时间段：
· 早上6-7点：通勤/起床 → 发布第一章
· 中午12-13点：午休 → 发布第二章
· 晚上7-9点：下班后/睡前 → 发布第三章
· 禁止：晚上10-12点发布（审核高峰）
```

### 步骤2：番茄流量三阶段运营

```
验证期（8万字）→ 首秀（14天）→ 长效推荐

| 阶段 | 核心指标 | 达标线 | 操作 |
|------|---------|--------|------|
| 验证期 | 前10章完读率 | ≥8% | 不达标直接切书 |
| 首秀 | 7日追读率 | ≥25% | 优化书名/简介/封面 |
| 首秀 | 10万字整体完读率 | ≥15%（脑洞文）/ ≥10%（爽文） | 书测决定去留 |
| 长效 | 日均阅读时长 | ＞60分钟 | 稳定更新等推荐 |
```

### 步骤3：崩文预防（悬念提前交替铺垫）

```
核心方法：第1个悬念还没揭晓时，就要开始铺垫第2个悬念。
不是快结束时才铺——那时读者注意力还集中在第1个悬念上，来不及转移。

具体操作：
1. 在悬念1的故事中穿插悬念2的人和事
2. 同时让悬念3的人物露个面
3. 写到悬念2时继续穿插悬念3的部分故事
4. 给悬念4的露面做铺垫
5. 让每个悬念的钩子至少保持在1.75个以上

钩子节奏公式：
一个钩子拆开的同时，另一个钩子已经套上了。
```

### 步骤4：换地图正确姿势

```
原则：不要过度描写主角路上的心理历程和目的地的环境描写。

核心：主角去拿东西，就写拿东西本身。
你写的是主角完成了多少事，而不是走过了多少地方。

错误做法：
· 大段描写路上的风景
· 大段描写主角的心理活动
· 大段描写新地图的环境
· 离开旧地图时拖泥带水

正确做法：
· 快速过渡，直奔新地图的核心冲突
· 新地图的设定通过冲突展示，不通过旁白介绍
· 旧地图的伏笔可以延伸到新地图，但不要大段回顾

保底策略：如果暂时掌握不好换地图技巧，最简单粗暴的办法是尽量不换地图。
```

### 步骤5：切书决策标准

| 数据区间 | 决策 | 动作 |
|---------|------|------|
| 验证期首日吸量＜200 | 直接切书 | 不要犹豫 |
| 10万完读率＜8% | 止损 | 写到20万做书测 |
| 10万完读率8%-15% | 书测后决定 | 优化书名封面再测 |
| 10万完读率＞15% | 坚持 | 写到50万字等第二波大推荐 |

```
切书原则：
· 数据是唯一客观标准，不要凭感觉
· 验证期首日吸量<200 → 直接切，不要恋战
· 完读率<8% → 止损，不要硬撑
· 完读率>15% → 坚持，等第二波推荐

最客观的判断标准：追更数据有没有掉？
```

### 步骤6：差评处理

```
核心原则：别让读者替你写大纲。

真实案例：有位作者把第一本书所有被骂的毒点全改掉了，
结果第二本扑得非常惨。原因——读者想要什么，作者不能立马给。

| 差评类型 | 处理方式 |
|---------|---------|
| 常识性错误 | 可以改 |
| 剧情向建议 | 慎重 |
| 追读稳但评论骂 | 不用改（边骂边看） |

判断标准：
· 追读数据没掉 → 不改
· 追读数据掉了 → 分析原因，慎重修改
· 常识性错误 → 立即改
```

## 模板/示例

### 模板1：连载运营日历

```markdown
【开书前】
□ 存稿至2万字（新手）/ 10万字（老手）
□ 完成黄金三章打磨
□ 准备3-5个备选书名
□ 完成简介（300字以内）

【验证期（0-8万字）】
□ 每日稳定更新
□ 监控前10章完读率（目标≥8%）
□ 准备首秀物料（书名/封面/简介优化）

【首秀期（8-14万字）】
□ 监控7日追读率（目标≥25%）
□ 监控10万字完读率
□ 根据数据决定：坚持/书测/切书

【长效期（14万字+）】
□ 监控日均阅读时长（目标>60分钟）
□ 保持存稿缓冲≥3章
□ 悬念交替铺垫，预防崩文
□ 等待第二波大推荐（50万字节点）
```

### 模板2：悬念交替铺垫模板

```
当前悬念1：______（揭晓节点：第____章）
  ↓ 穿插
悬念2铺垫：______（人物/事件露面）
  ↓ 同时
悬念3铺垫：______（人物露面）
  ↓
悬念1揭晓 → 悬念2开始
  ↓ 穿插
悬念3部分故事
  ↓ 同时
悬念4铺垫
  ↓
悬念2揭晓 → 悬念3开始
...

钩子数量自检：每章钩子≥1.75个
禁止连续两章没有钩子
```

## 自检清单

- [ ] 存稿缓冲是否≥3章？
- [ ] 章节字数是否控制在2050-2300字（番茄平台）？
- [ ] 每千字新设定曝光是否≤15条？
- [ ] 更新时间段是否避开了晚上10-12点？
- [ ] 悬念是否提前交替铺垫（第1个未揭晓就铺垫第2个）？
- [ ] 每章钩子数量是否≥1.75个？
- [ ] 是否避免了连续两章无钩子？
- [ ] 换地图时是否避免了过度描写路上心理和环境？
- [ ] 切书决策是否基于客观数据（追读率/完读率）？
- [ ] 差评处理是否遵循"追读没掉就不改"原则？

## 适用边界

- **适用**：所有网文连载平台（番茄/起点/纵横/七猫/晋江）
- **强适用**：番茄小说（章节字数、流量机制、切书标准针对番茄优化）
- **弱适用**：起点等付费平台（数据指标和切书标准需调整）
- **不适用**：完结作品的一次性发布（无需运营）
- **慎用**：新手第一本书（数据指标仅供参考，新手更需积累经验）
